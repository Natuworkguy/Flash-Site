THE DIFFERENCE THAT MATTERS

Most AI terminals
upload your code.

They run commands on your machine, which makes them look local. The model doing the thinking still sits on someone else's server, and everything you send it goes there first. FLASH moves the model too.

The one exception is opt-in and labelled before you pull it: a cloudbase tag runs the model on a hosted base, for trying Onyx without a {{onyx.cloud.localSize}} download.

“Pi and Aider can run local models too.”

True. Agents like Pi, Aider and OpenCode will happily talk to a model on your own box. They're good tools. The difference isn't whether local is possible, it's what you get handed when you start.

  1. They ship a harness. FLASH ships both halves. Pi is model-agnostic by design: read, write, edit, bash, and whatever model you point it at. That's genuinely flexible, and it also means the agent's behaviour is entirely your model's problem. Aim a stock local model at a generic tool loop and you get padding, hedging, an opening “Perfect!”, and work reported as done that was never run. Flash Onyx is a {{onyx.baseModel}} retrained against exactly those failures, and it is one ollama pull away.
  2. Local is the default, not a backend you wire up. Multi-provider agents are built around provider keys and subscription logins, with a local endpoint as one option among twenty. FLASH has no other mode. There is no key to bring, no account to make, and no path where your code quietly goes somewhere else because a fallback kicked in.
  3. The shell is a real terminal, not a pipe. Anything you run with ! gets a live interactive channel, so password prompts, ssh, and full-screen editors work instead of hanging a captured stdout. Secrets you type go to your terminal's masked input: FLASH never sees them.

Where Pi wins: if you want one harness driving frontier cloud models, or you're on Node and want to extend it in TypeScript, it's the better fit. FLASH is for the case where the model itself has to stay on your hardware.
