Other AI services have started watermarking what they generate. {{onyx.version}} doesn't, and you don't have to take that on faith. A text watermark isn't in the weights, it's a keyed sampler a provider bolts on at generation time, behind an endpoint you can't read. Cloudbase: the 31B without the 19.9 GB

New since 2.2. The {{onyx.cloud.tag}} tag ships the Onyx prompt and sampling with no weights behind them, pointed at {{onyx.cloud.hostedBase}}, a {{onyx.baseModel}} Ollama hosts: same behavior as the local 31B, {{onyx.cloud.downloadSize}} to pull instead of {{onyx.cloud.localSize}}. Run {{onyx.cloud.signinCmd}} once first. There's no 12B cloudbase, because {{onyx.baseModel}} hosts no 12B to build one on, and the 12B is 7 GB anyway. Either way your tools still run here: cloudbase moves the inference, not FLASH.

Read this part before you use it. Cloudbase sends your prompts to a hosted base model, so it walks straight past the local in Fast Local Agent SHell. It's the right call for trying Onyx before a {{onyx.cloud.localSize}} pull, for a laptop that can't hold a 31B, and for work you'd be fine posting publicly. Coming from Onyx 2.2 or 2.3? Nothing else changes: swap the tag and carry on. 2.4 is a prompt release, the same weights and the same ten sampling lines as 2.3 behind a prompt that got 9 lines shorter, so the pull mostly reuses layers you already have. Every tag from Onyx 2 on carries a size, so a bare flash-onyx-2.4 doesn't resolve: use {{onyx.small.tag}}, {{onyx.large.tag}}, or {{onyx.cloud.tag}}, and switch with {{onyx.selectCmd}}. Replies stay short by default, ask for the long version when you want one. Onyx 2.3, 2.2, 2.1, 2, and 1 are all still here and still build, and 2.3 has a flash-onyx-2.3:31b-cloudbase tag of its own if you're pinned to it.
